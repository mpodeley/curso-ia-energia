### Qué decide sistemas

Casi todo lo que hace falta lo prende o lo apaga un administrador, en tres lugares distintos:

| Dónde | Qué controla | Fuente |
| --- | --- | --- |
| Políticas de GitHub (organización o empresa) | Servidores MCP, agentes de terceros, qué modelos se pueden elegir, funciones en vista previa, Copilot CLI. La de la empresa le gana a la de la organización | [GitHub Docs](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-organization/manage-policies) |
| Políticas de VS Code en Windows | Si hay modo agente (`ChatAgentMode`), si hay MCP (`ChatMCP`), qué servidores se permiten, si se aprueban herramientas solas, qué extensiones se instalan | [VS Code, Enterprise policies](https://code.visualstudio.com/docs/enterprise/policies) |
| Configuración de Microsoft Copilot | Si se usan modelos de Anthropic. Vienen prendidos, salvo en la Unión Europea, la Asociación Europea de Libre Comercio y el Reino Unido | [Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-365/copilot/connect-to-ai-subprocessor) |

Los modelos de Claude y GPT aparecen en el selector de GitHub Copilot, y "an enterprise or
organization administrator must still enable each model"
([Supported models](https://docs.github.com/en/copilot/reference/ai-models/supported-models)).
Los agentes de terceros en GitHub, Claude y Codex, están en vista previa pública y dependen de una
política. Esa política no alcanza a los agentes locales de VS Code
([About third-party agents](https://docs.github.com/en/copilot/concepts/agents/about-third-party-agents)).

Lo que conviene pedirle a sistemas, en un solo mail:

1. ¿Tenemos GitHub Copilot Business o Enterprise? ¿Está habilitado el modo agente en VS Code?
2. ¿Qué modelos están habilitados en el selector?
3. ¿Se permiten servidores MCP? ¿Hay una lista de servidores aprobados?
4. ¿Está habilitado Copilot CLI?
5. ¿Qué clase de datos se pueden usar con estas herramientas?

### Receta: un agente tipo Claude Code con GitHub Copilot

Supone que la empresa tiene GitHub Copilot con el modo agente habilitado. Todo se hace sin permiso
de administrador.

1. **Instalá VS Code con el instalador de usuario.** El "User setup" "does not require
   administrator permissions" y queda en `%LOCALAPPDATA%\Programs\Microsoft VS Code`
   ([VS Code en Windows](https://code.visualstudio.com/docs/setup/windows)). El "System setup",
   para todos los usuarios de la máquina, sí pide administrador.
2. **Entrá con la cuenta de GitHub de la empresa.** La extensión de Copilot viene integrada;
   abrí el chat y pasalo a modo agente.
3. **Abrí una carpeta de trabajo.** Una copia, como en la sesión 5. El agente lee, propone
   cambios y pide permiso antes de correr comandos.
4. **Dejá las reglas por escrito.** GitHub Copilot lee `.github/copilot-instructions.md`, y
   también `AGENTS.md` y `CLAUDE.md`
   ([instrucciones del repositorio](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions)).
   El AGENTS.md de la sesión 5 sirve tal cual. En VS Code, la lectura de CLAUDE.md depende de la
   opción `chat.useClaudeMdFile` ([Custom instructions](https://code.visualstudio.com/docs/copilot/customization/custom-instructions)).
5. **Guardá los pedidos que repetís.** Un archivo `.github/prompts/partes.prompt.md` se llama
   después como `/partes` en el chat ([Prompt files](https://code.visualstudio.com/docs/copilot/customization/prompt-files)).
   Es lo más parecido a una skill chica.
6. **Si la política lo permite, conectá un servidor MCP.** Por ejemplo el de tNavigator, más abajo.
7. **Si preferís la terminal,** Copilot CLI se instala con `winget install GitHub.Copilot` o con
   `npm install -g @github/copilot`, y pide Node.js 22 o posterior
   ([Install Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli)).

Para probarlo, repetí el caso de la sesión 6, el tablero de Volve, con el mismo AGENTS.md. Es un
dataset público, así que no hay nada de la empresa en juego.

### Claude Code

Es el agente de terminal de Anthropic, el de la demo de la sesión 5. Pide un plan Pro o superior,
o una cuenta de empresa (Team o Enterprise), o que la empresa lo conecte por su nube: Amazon
Bedrock, Google Cloud o Microsoft Foundry
([proveedores](https://code.claude.com/docs/en/third-party-integrations)).

**Instalación sin administrador.** En PowerShell:

```powershell
irm https://claude.ai/install.ps1 | iex
```

La documentación lo dice explícito: "You do not need to run as Administrator"
([Setup](https://code.claude.com/docs/en/setup)). Queda en `%USERPROFILE%\.local\bin` y se
actualiza solo. Git for Windows es opcional: si está, el agente usa Git Bash; si no, usa
PowerShell. Pide Windows 10 1809 o posterior.

**Detrás de un proxy corporativo.** Claude Code respeta `HTTPS_PROXY` y confía en los
certificados del sistema operativo, así que un proxy que inspecciona el tráfico suele andar sin
tocar nada. Si no anda, `NODE_EXTRA_CA_CERTS` apunta al certificado de la empresa. Los proxies
con autenticación NTLM o Kerberos necesitan otro camino, una pasarela intermedia
([Network configuration](https://code.claude.com/docs/en/network-config)). Las variables se
guardan en el bloque `env` de `~/.claude/settings.json`:

```json
{
  "env": {
    "HTTPS_PROXY": "<la dirección del proxy que te pase sistemas>",
    "NODE_EXTRA_CA_CERTS": "C:\\Users\\tu-usuario\\certificados\\empresa.pem"
  }
}
```

**Qué puede fijar sistemas.** Una configuración administrada, en el registro de Windows o en
`C:\Program Files\ClaudeCode\managed-settings.json`, le gana a la tuya: permisos, modelos,
servidores MCP ([Managed settings](https://code.claude.com/docs/en/managed-settings)).

### Claude Cowork

Cowork es "the same agentic architecture that powers Claude Code, with no terminal required": el
mismo agente, desde la aplicación de escritorio de Claude y sin terminal, para planillas,
documentos y carpetas ([Get started with Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork)).
Está en los planes pagos: Pro, Max, Team y Enterprise.

**Sin administrador, Cowork de escritorio no anda.** La guía de instalación para Windows es
directa: "Users without admin access can still install Claude, but Cowork on desktop will not be
available" ([Deploy Claude Desktop for Windows](https://support.claude.com/en/articles/12622703-deploy-claude-desktop-for-windows)).
Cowork corre en una máquina virtual aislada y necesita la función Virtual Machine Platform de
Windows, que se prende con permisos de administrador y un reinicio. La aplicación de Claude sí se
instala; lo que queda afuera es Cowork.

Dos caminos:

1. **Que sistemas lo instale para toda la máquina.** La misma guía muestra cómo: prende la
   plataforma de máquinas virtuales y aprovisiona el paquete para todos los usuarios. Después,
   cualquier usuario sin permisos lo usa.
2. **Cowork en la web.** Está en beta en la web y el celular para Pro, Max y Team. En Enterprise
   viene apagado hasta que lo prende un administrador
   ([Cowork en web, escritorio y celular](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile)).
   Corre en la nube de Anthropic, así que trabaja con lo que le subís, sin acceso a tu disco.

### Codex

Codex es el agente de OpenAI. Viene como aplicación de terminal (Codex CLI), extensión de VS Code
y aplicación de escritorio, y pide un plan pago de ChatGPT (Plus, Pro, Business, Edu o
Enterprise) o una clave de la API.

**Instalación de la terminal sin administrador.** Cualquiera de las dos, según el
[repositorio oficial](https://github.com/openai/codex):

```powershell
# Instalador de OpenAI
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"

# O con npm, si ya tenés Node.js
npm install -g @openai/codex
```

**El aislamiento cambia sin administrador.** En Windows, Codex encierra los comandos en un
sandbox. El modo "elevated" crea usuarios aparte y reglas de firewall, y eso pide aprobación de
administrador. Sin ese permiso, Codex pasa al modo "unelevated": limita los archivos con permisos
comunes y aísla menos la red ([Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox)).
Anda igual, con menos protección, así que ahí conviene empezar con la aprobación manual. La misma
página recomienda Windows 11.

**La aplicación de escritorio** se instala desde Microsoft Store, sin administrador
([Codex para Windows](https://learn.chatgpt.com/docs/windows/windows-app)). En muchas empresas la
Store está bloqueada; entonces queda la terminal o la
[extensión de VS Code](https://marketplace.visualstudio.com/items?itemName=openai.chatgpt).

**Qué decide el administrador en Enterprise.** Codex local y Codex en la nube son dos
interruptores separados, y "Codex Cloud is off by default for Enterprise workspaces"
([Admin setup](https://learn.chatgpt.com/docs/enterprise/admin-setup)).

### Las herramientas de base, sin administrador

Copilot CLI y Codex por npm necesitan Node.js. Los scripts que arma un agente necesitan Python.
Las dos cosas se instalan en tu usuario:

| Qué | Cómo, sin administrador | Dónde queda | Fuente |
| --- | --- | --- | --- |
| Node.js | Bajá el `.zip` de Windows (no el `.msi`) y descomprimilo en una carpeta tuya | Donde lo descomprimas | [nodejs.org](https://nodejs.org/en/download) |
| Paquetes de npm | `npm install -g` ya escribe en tu usuario | `%AppData%\npm` | [npm folders](https://docs.npmjs.com/cli/v11/configuring-npm/folders) |
| Python | `uv` baja su propio Python, sin tocar el del sistema | `~\.local\bin` | [uv](https://docs.astral.sh/uv/getting-started/installation/) |
| Git | PortableGit, un archivo que se descomprime | Donde lo descomprimas | [git-scm.com](https://git-scm.com/install/windows) |
| Varios a la vez | Scoop, un gestor de paquetes que se niega a correr como administrador | `~\scoop` | [Scoop](https://github.com/ScoopInstaller/Install) |

<details>
<summary>Para curiosos: los comandos, y cómo agregar una carpeta al PATH</summary>

El PATH es la lista de carpetas donde la terminal busca los programas. Windows tiene uno del
sistema, que pide administrador, y uno de tu usuario, que no. Para agregar la carpeta de Node.js
al tuyo, en PowerShell:

```powershell
$dir = "$env:USERPROFILE\herramientas\node"
$actual = [Environment]::GetEnvironmentVariable('Path', 'User')
[Environment]::SetEnvironmentVariable('Path', "$actual;$dir", 'User')
# Cerrá y volvé a abrir la terminal para que tome el cambio
```

Lo mismo con el mouse: en el menú Inicio buscá "variables de entorno" y elegí la opción de tu
cuenta, la que no pide administrador.

```powershell
# uv y un Python propio
irm https://astral.sh/uv/install.ps1 | iex
uv python install

# Scoop, y con Scoop, Node.js y Git
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
irm get.scoop.sh | iex
scoop install nodejs-lts git
```

Si la política de la empresa bloquea `Set-ExecutionPolicy` o los scripts de PowerShell, eso es
una decisión de sistemas. No la esquives.

</details>

## IA dentro de tNavigator, Petrel e INTERSECT

Los tres traen IA, y de tres clases distintas. Conviene separarlas porque se evalúan distinto:

- **El asistente que conversa** es un modelo de lenguaje (large language model, LLM) adentro del
  programa, con el arnés que armó el fabricante. Es lo de las sesiones 2 y 5, con las mismas
  alucinaciones posibles.
- **El aprendizaje automático** (machine learning, ML) sobre el modelo existe hace años: redes
  entrenadas con corridas del simulador, o con datos de pozo. Es el aprendizaje supervisado de la
  sesión 1.
- **La puerta para tu agente** es una interfaz de programación (application programming
  interface, API) en Python, o un servidor MCP. Con eso, un agente como Claude Code, Copilot o
  Codex maneja el programa desde afuera, con tus permisos y tu AGENTS.md. Es lo de las sesiones 5
  y 6.

que entrena proxies con redes neuronales ([IA y ML en tNavigator](https://rfdyn.com/industries/machine-learning-ai/)).

### Cómo funciona un proxy del simulador

La capa 2 es la más vieja y la que más se usa en ajuste histórico. Un proxy es un modelo de
aprendizaje supervisado entrenado con corridas del simulador:

<figure className="figura">
  <img
    src="slides/img/preguntas-proxy.svg"
    alt="Cinco pasos: parámetros inciertos; cientos de corridas del simulador, horas cada una; una tabla de ejemplos de entrada y salida; un proxy entrenado que responde en segundos; miles de preguntas para ajuste histórico, P10, P50 y P90 y optimización. Una flecha punteada vuelve al simulador para confirmar los casos que importan. Dos avisos: el costo está en las corridas de entrenamiento, y fuera de rango el proxy se equivoca sin avisar."
  />
</figure>

Es el mismo mecanismo de la sesión 1: ejemplos con respuesta, un modelo que aprende la relación y
un error que se mide con datos que el modelo no vio. Y vale lo que dice la sesión 8: la simulación
sigue siendo trabajo de reservoristas. El proxy acelera la exploración, y el caso que se lleva a
una decisión se corre en el simulador.

<details>
<summary>Para curiosos: qué está haciendo la investigación</summary>

- **Operadores neuronales.** U-FNO predijo la migración de CO₂ unas 10,000 veces más rápido que
  el simulador en los casos de prueba de sus autores ([Wen y otros, 2022](https://arxiv.org/abs/2109.03697)).
  La versión anidada llegó a escala de cuenca ([Wen y otros, 2023](https://arxiv.org/abs/2210.17051)).
- **Redes sobre grafos,** para grillas irregulares y optimización de pozos
  ([Stanford, 2024](https://arxiv.org/abs/2312.08625)).
- **NVIDIA PhysicsNeMo** trae un ejemplo entrenado con corridas de OPM Flow sobre Norne, un campo
  público. Su documentación reconoce que los errores "accumulate over time"
  ([ejemplo](https://docs.nvidia.com/physicsnemo/26.08/physicsnemo/examples/reservoir_simulation/xmgn/README.html)).
- **Agentes que arman modelos.** JutulGPT, de SINTEF, es un agente que construye modelos de
  simulación en JutulDarcy, los corre y los valida en un loop, y marca las ambigüedades del pedido
  ([Lie y otros, 2026](https://arxiv.org/abs/2603.00214)). En ADIPEC 2025 hubo varios trabajos de
  agentes sobre simuladores, por ejemplo uno con 18 herramientas y búsqueda en documentos
  ([SPE-229646-MS](https://onepetro.org/SPEADIP/proceedings-abstract/25ADIP/25ADIP/D021S069R002/793001)).

Las velocidades de estos papers se miden después de entrenar y sobre los casos de sus autores. El
costo de las corridas de entrenamiento queda afuera de la cuenta.

</details>
